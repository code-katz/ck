The validator passed it on the first try. The roster rule from 0.1.4 held: the document counts the roster nowhere.

## What broke

1. **The validator did not count.** `TEAM.md` is 2,685 words by `wc -w`; the contract caps it at 2,500. The Haiku validator wrote "approximately 1,200 to 1,500 words, well under" and passed it. The 0.1.4 counting rule went into the `draft` workflow only; the team, market-research, roadmap, opportunity, brand, and design validators still judge length by impression.
2. **No run record, nobody owns the review.** Typed directly, `/ck:team` lands in `.ck/runs/team-latest` with the run id `team-direct`, no `run.json`, and the placeholder date in its result; the ck-test session rendered and published the review page by hand. The same gap the brief had before 0.1.3, and `/ck:roadmap` and `/ck:market-research` have it too.
3. **Confirmations read everything.** Each of the eight nominees reads the full PRD and the opportunity analysis to confirm a seat and name a missing one; the three Fable nominees alone cost $3.95.

For Will's review, not a plugin bug: Kai's confirmation found that the PRD's AC7.6 sample overflows 80 and 120 columns and contradicts AC8.5 on alignment, a finding against the finalized PRD.

## The fix in 0.1.6

1. The team, opportunity, design-spec, and market-research validators count with `wc -w` and quote the count; a test checks every capped workflow for it.
2. `/ck:team`, `/ck:roadmap`, and `/ck:market-research` are skills that mint the run and own the review; the workflows are `ck:team-draft`, `ck:roadmap-draft`, `ck:market-research-draft`.
3. Nominees read River's nomination and the brief, and a PRD requirement only when a responsibility names it.
4. Found on the way: the brand and design gallery validators looked for `@claude` in a banner that no longer carries it. Fixed.

Re-measure `/ck:team` on 0.1.6: expected about $6, with the validator's count in its notes.
